# feature manager：製品クラスごとの差分はコード内の比較で実装されている

実験1（`0x02cf1700 MODE_SHUTTER` を `01` にしてもシャッター角表示にならない）の
理由を探すために、`appFw.so` の feature manager を構造から見直した結果。
すべて静的解析で、`scripts/feature_manager_getters.py` で再現できる。

## 仕組み

パラメータ1件が6命令のスタブになっている：

```asm
adrp x0, <page>            ; ldrsw x1, [x0, #0x5b0]   ← 製品クラスの index
adrp x0, <page>            ; add   x0, x0, #<off>     ← このパラメータのテーブル
ldr  w0, [x0, x1, lsl #2]  ; ret                      ← table[class]
```

- 製品クラス index のグローバルは **`0x5bc35b0`**（`.data`）。
- テーブルは1クラス4バイト × **26クラス**。
- 呼び出し側は戻り値を**その場で定数と比較する**。たとえば

  ```asm
  bl   menu_item_getter
  cmp  w0, #0x13          ; クラス19か
  b.eq ...
  bl   menu_item_getter
  cmp  w0, #0x14          ; クラス20か
  b.ne ...
  ```

  という形で、**A7C II（`PP` = 9）は else 側に落ちる**。

つまり機種差は「クラスごとのメニュー定義テーブル」ではなく、
**コード内に散らばった比較**として実装されている。

## 規模

| 項目 | 実測 |
| --- | --- |
| getter スタブ | **122件**（`0x1797d44`〜`0x179889c`） |
| うち `PRM_FEATURE_MANAGER_*` の名前が残っているもの | **39件** |
| 呼び出し箇所 | **5,991件**（99スタブ分） |

**名前が引けるのは3分の1以下。** 残り83件は無名のまま per-class テーブルを
持っている。`feature_manager_matrix.py` が出す39件は全体ではない。

呼び出しの多い順（抜粋）：

| `(unnamed) 0x17983bc` | 2528 |
| `(unnamed) 0x17987ac` | 1676 |
| `system_architecture` | 191 |
| `(unnamed) 0x179829c` | 177 |
| `shoot_mode_switch` | 168 |
| `menu_item` | 116 |

`menu_item`（スタブ `0x1797d44`、テーブル `0x370ce60`、A7C II は **9**）の
116箇所で比較されている定数を数えると：

| 定数（クラス） | 箇所数 |
| --- | --- |
| 9（**PP = A7C II**） | 11 |
| 10 | 11 |
| 24 | 10 |
| 20 | 8 |
| 25 | 8 |
| 2 / 19 | 7 |
| 11 | 6 |
| 5 | 5 |
| その他（1,3,4,6,8,21,23） | 1〜4 |
| 直後に即値比較が無いもの | 26 |

PP 専用の分岐が11箇所ある一方、他クラス向けの分岐からは外れている。

## 実験1との関係

**シャッター角の近くに feature manager の判定は無い。**
`MODE_SHUTTER` のコンストラクタ参照（`0x2ef5984` / `0x2ef5a34`）から
**±16 KB の範囲に、122スタブのいずれの呼び出しも存在しない**。

したがって「menu_item がクラス9を弾いている」という当初の仮説は、
少なくとも**この近傍では裏付けられない**。実験1が効かなかった理由は別にある：

- `MODE_SHUTTER` 以外に前提となるプロパティがある
- メニュー項目そのものが別のデータ（メニュー定義リソース）側で決まる
- そもそもこのプロパティが読まれていない

## ここから言えること

1. プロパティを1件立てるだけで開く機能は、**たまたまコード側に分岐が無いもの**に限られる。
   分岐がある機能は、プロパティではなく**コード（`appFw.so`）側の改変**が必要で、
   それは p15 が読み取り専用マウントである以上、フラッシュか RAM パッチの話になる。
2. 無名の83件を含む122件のテーブルは、**機種間の差分を一覧できる地図**になる。
   どのクラスで何が有効かが分かるので、「A7C II で何が潜在的に可能か」の
   見積もりに使える。
3. 製品クラス index（`0x5bc35b0`）を書き換えれば挙動はまるごと別クラスになるが、
   調整値やキャリブレーションに関わる判定も同時に変わる。**試すべきではない。**

## 製品クラスと配列添字の対応（2026-11-24 確定）

**`feature_manager_matrix.py` が出す製品クラスの並び順は、テーブルの配列添字と
同じではない。逆順である。**

確定のしかた：名前が残っている39件すべてについて、
`table[i]` が行列スクリプトの各クラスの値と一致する添字 `i` を探すと、
**どのクラスも一意に決まり、39件が39件とも一致する**。

| 添字 | クラス | | 添字 | クラス |
| --- | --- | --- | --- | --- |
| 0 | DOC | | 13 | TAKE_BASIC |
| 1 | MT | | 14 | ATOM |
| 2 | RS | | 15 | SP |
| 3 | HC | | **16** | **PP ＝ A7C II** |
| 4 | NE | | 17 | OS |
| 5 | OT_UUD | | 18 | YS |
| 6 | TK_UUD | | 19 | DZ |
| 7 | ALCIN2 | | 20 | SA |
| 8 | LUKE | | 21 | YT |
| 9 | CHAPLIN | | 22 | GL |
| 10 | EREN | | 23 | ALCIN_UUD |
| 11 | POTTER | | 24 | LAX |
| 12 | HARRY | | 25 | LS |

つまり **A7C II は各テーブルの添字 16 を読む**。
`menu_item` の `table[16]` は **9** で、行列スクリプトの `PP = 9` と一致する。
前の節に書いた「`menu_item` は PP で 9、PP 名指しの分岐は11箇所」は**そのまま有効**。

全122件の値と、クラスごとの一致状況は
[evidence/feature-manager-a7cii-classmap.json](../evidence/feature-manager-a7cii-classmap.json)。

## A7C II が他クラスと違う点はごく少ない

| 条件 | 件数 |
| --- | --- |
| 122件中、A7C II の値が**26クラスで唯一** | **3件** |
| A7C II が3クラス以下の少数派 | 1件 |
| 全クラスが同じ値（機種差なし） | 5件 |

唯一になる3件：

| スタブ | 名前 | A7C II の値 | 異なる値の数 | 呼び出し |
| --- | --- | --- | --- | --- |
| `0x1797d44` | `menu_item` | 9 | 26 | 116 |
| `0x1797d5c` | `camera_parameters` | 9 | 20 | 19 |
| `0x1797d74` | **（無名）** | 9 | 19 | 9 |

3件目は名前が残っていない3つ目の「機種識別子」。`menu_item` /
`camera_parameters` と同じく機種ごとに別値を持ち、9箇所で参照されている。

少数派の1件：

| 名前 | A7C II の値 | 同じ値のクラス |
| --- | --- | --- |
| `imager_model` | **0** | DOC、LS、PP |

`imager_model` の値0は、行列スクリプトでは `TYPE_IMAGER_MODEL_IMX710` という
ラベルが残っている。**A7C II は LS クラスと同じセンサー型**ということになる。
オープンゲート側で特定した読み出しモードテーブル（7008x4672 と 7008x3942）が
A7 IV のものと同じ構造だったことと整合する。

### 読み方

「A7C II だけ違う」のが3件しかないという事実は、**機能の有効/無効が
feature manager で機種ごとに切られているわけではない**ことを意味する。
大半のパラメータでは A7C II は多数派の側にいる。
したがって、ある機能が A7C II で出ないことの説明を feature manager に
求めても、たいていは見つからない（実験1がまさにそれだった）。
